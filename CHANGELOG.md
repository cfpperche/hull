## [Unreleased]

### Added

- **Hull can speak more than one language, and the mail already does.** It spoke English and did not know it: `lang="en"` was fixed in four places, nothing in the system could be asked which language a person reads — and one thing was answering anyway. The session list formats "last used" through `Intl.RelativeTimeFormat(undefined, …)`, which takes the *browser's* language, so a Brazilian reader was being served **"Last used há 4 minutos"**: half a sentence in each language, on a screen shipped this month. The shape is one catalog per locale in `packages/i18n` with three consumers — the screens read it in the browser, the mail is rendered against it at build time, and API errors will come back as codes the browser looks up. **The server never translates a string; it picks a pre-rendered file.** That is what keeps a second catalog, and an i18n library, out of Python and Node out of the send path. No i18n library at all: key lookup and interpolation are sixty lines, and the missing-key warning an ecosystem would have given us is a build gate that fails when two locales disagree — including when a translation quietly dropped `{oldEmail}` out of the middle of a sentence, which TypeScript cannot see. `users.locale` is set on the Account page and captured at signup from `Accept-Language` rather than a body field, because the welcome mail goes out inside that request and a client that forgot to send one would silently mail a Portuguese reader in English. Mail goes in the **recipient's** language — an operator working in English who triggers a notice to a Brazilian customer sends it in Portuguese, because there is no browser on the receiving end to ask. Seven messages × two languages, subject included: the subject used to be built in `Settings`, which put one half of every message in Python and the other in the JSX. English and `pt-BR` — one locale proves nothing, since a catalog with a single language cannot fail its own completeness check. The screens themselves are still English; that is the next delivery, and 132 strings riding on a ladder nobody had watched work is how it would have gone wrong. → [ADR-0016](docs/adr/0016-one-catalog-per-locale-the-server-never-translates.md)

- **The admin console has an account page.** It had none, and the product's was out of reach: a platform admin who is not impersonating is bounced from `app.` straight back to the console. So an operator could not change their own password or address, and could not see their own sessions — the one list that shows the support sessions they take into customers' workspaces, and the only way to end a device they no longer hold. The bounce stays: it is a domain rule, not an accident, and an operator has no workspace, so the product would meet them with "name your first workspace". The four sections moved to `@hull/ui` — `ProfileForm`, `EmailSection`, `PasswordForm`, `SessionList` — each taking the client as a prop rather than importing one, so both surfaces compose the same pieces and neither page owns the logic. That is shell rather than product, which is the same reason `ThemePreference` already lives there. The console's page deliberately has no **Close account**: `close_account` refuses a `platform_admin`, so the button would exist only to answer 403, and a browser test asserts it is absent.

- **The mail looks like the product.** Six transactional messages went out as plain text, so the one moment a person meets the brand outside the browser looked like nothing at all. They are now `multipart/alternative` — the plain half is the wording this install always sent, unchanged, because it is what a text-only client shows and what deliverability rests on; the HTML half is an alternative, never a replacement. The bodies are **react-email JSX** in `packages/email`, rendered once at build time into `hull_fastapi/mail_templates/` with `{{name}}` where a value goes, and filled in by `mail_compose` at send. React is not in the request path: putting Node behind SMTP would mean a second runtime in the compose group for six messages. The design is `AuthScreen` translated into what mail clients actually run — tokens as hex, because `packages/ui/src/styles.css` states them in `oklch()` and Gmail drops colour functions it does not know; inline styles and tables, because every client strips `:root`; one light design, because `prefers-color-scheme` works in Apple Mail and almost nowhere else; and the brand mark drawn as a letter in a box rather than fetched, because a hosted logo is blocked by default and arrives as a broken icon. White-label still reaches it — the name, the mark and the host come from Settings (ADR-0006); only the design is fixed. Two guards run in CI: the build refuses a placeholder that is not declared in `vars.ts`, and `pnpm --filter @hull/email check` fails if the generated files have drifted from the JSX. There is deliberately **no runtime editor**: an install that can rewrite its own password-reset mail while running has a new way to break account recovery.

- **Seeing where you are signed in, and ending it.** Sessions have been per-device since PR #5 and nothing surfaced them: a user could not see the laptop they left at an old job, let alone end it. `GET /v1/me/sessions` lists the live ones, `DELETE /v1/me/sessions/{id}` ends one, `DELETE /v1/me/sessions` ends everywhere but here. **No password on any of them** — revoking only takes access away, and putting a credential in front of the safe action is backwards at the moment somebody stops trusting a device. Ownership is enforced *inside* the delete rather than checked around it, since the id travels in the URL and is not a secret; another user's id answers 404 and the row survives. Two new columns make the list readable: a `User-Agent`, read by a deliberately dumb matcher into "Chrome on Windows" (User-Agent is a pile of historical lies — every browser claims to be Mozilla, Edge claims to be Chrome — so a library that keeps up with it is a dependency and a subscription, and this only has to answer "which of these is the machine in front of me"), and `last_seen_at`, stamped on use **at most once a minute** so a page firing five requests does not write five times. No IP address, deliberately: it costs a trusted-proxy decision and a store of location data this install has no other reason to hold. A support session shows in the operator's own list, marked as one, because it is theirs and an unexplained extra row would read like a break-in. Twenty-two server tests and one browser test, with four violations planted and watched to fail.

- **Changing the address you sign in with.** The login identifier was immutable: `ProfileBody` accepted a username and a display name and nothing else, so a typo at signup was permanent and anyone whose address belonged to a job they left had no way out. `POST /v1/me/email` asks; `POST /v1/auth/email` redeems. The split matters — **nothing changes when you ask.** The old address keeps signing in and keeps receiving reset mail until the *new* one opens its own link, so a link sitting unread in a mailbox never costs anybody their sign-in. The current password is confirmed at the request, not the redemption, because that is the step a stolen cookie would reach; what the link proves afterwards is narrower, only that somebody reads the new mailbox. Redeeming marks the address verified in the same statement that moves it, since asking for the same proof twice is theatre. The address that is losing the account is mailed twice: once while it can still act, and once when it is done — and **changing the password cancels every pending change**, which is what turns "if this was not you, change your password" from advice into a control. Sessions survive on purpose; a reset kills them because it is what someone does after losing control, while this is a deliberate edit that would otherwise sign you out of the laptop because you finished on your phone. `email_changes` is the fourth table with the shape `password_resets` set: hashed at rest, single use, `used_at IS NULL … RETURNING`, token in the fragment. Nineteen server tests and one browser test, with the guards proven by planting five violations and watching each fail — including one that caught the browser test itself asserting nothing, because the address it moved to contained the address it moved from.

- **Email verification.** The address was collected at signup, mailed once and never confirmed, so nothing in the install knew whether it reached anybody. Password reset made that matter: recovery is handed to whatever was typed in that box. `POST /v1/auth/verify` redeems a link folded into the welcome mail — one mail, not two, since a welcome and a separate "confirm your address" is the pair people learn to ignore — and `POST /v1/me/verify` sends it again. Same shape as the other tokens: hashed at rest, single use, `used_at IS NULL … RETURNING`, and the token in the fragment. Public on purpose: the link is opened from a mail client, often on another device, and it grants nothing that a session would protect. `email_verifications` stores **the address the link was sent to**, not just the user, so a link minted before an address change cannot rubber-stamp the one that replaced it. Unverified accounts get a quiet banner with a resend; nothing is blocked, because nothing in Hull requires a confirmed address yet — the first thing that will is changing your email. The seeded lab users start verified: a fixture that opens every session asking you to click a link in a mailbox that does not exist is one people learn to skip. Completes the lifecycle in ADR-0011.

- **Password reset.** Until now a user who forgot their password was locked out permanently: `/v1/me/password` needs a session, and nothing else could reach the account. `POST /v1/auth/forgot` mails a single-use link and `POST /v1/auth/reset` redeems it — `password_resets` mirrors `support_handoffs` row for row and is claimed with the same `used_at IS NULL … RETURNING`, so two clicks on one link cannot both win. The token rides in the URL **fragment**, like the support hand-off, so it never reaches an access log or a `Referer`; the page strips it before the form is drawn. Redeeming ends **every** session of that user, because a reset is what someone does when they believe an attacker holds one. `/v1/auth/forgot` answers 204 whether or not the address exists — a distinguishable response would make it a membership oracle — and it already sits behind the Traefik rate limit on `/v1/auth/*`. Decided in ADR-0011, which moves from `Proposed` to `Accepted`.
- `scripts/reset-lab.sh` (`make reset`) puts the lab back to the demo fixture in a couple of seconds. Nothing did this before: `migrate.sh` inserts the seed `WHERE NOT EXISTS` and records it in `schema_seeds`, so once ada exists with a changed password it prints `skip 001_lab.sql` and leaves her broken; the only way back was `down.sh -v && up.sh`, which drops the volumes and rebuilds every image to undo one password. This truncates every table except `schema_migrations` — discovered from `pg_tables` rather than listed, so a table added later cannot be silently missed — re-applies the seed, empties Mailpit and clears the avatar bucket. All three, because a half reset is worse than none: yesterday's reset link would otherwise still be the newest mail for an address the fixture just recreated. Refuses outside a `.test` apex and with `HULL_SEED_DEMO=0`, for the same reason `migrate.sh` does — the fixture installs a `platform_admin` whose password is in the README. The lab had accumulated 242 users, 195 workspaces and 251 messages from test runs before this existed.
- `qa.sh mail` reads Mailpit from the QA harness. Some flows only exist in an inbox — a reset link is in no response body — so driving them from the browser alone stops halfway.
- **`harness/scripts/peer.sh` — the three agents can now ask each other.** Claude, Codex and Grok all work in this repo and had no channel between them: each read `AGENTS.md`, worked, left files, and the next one read the tree. `peer.sh ask` delegates, `review` gets a diff read against a fixed schema, `audit` puts one claim to a peer as confirmed / refuted / unproven, and `duel` runs a blind round-1 review by both peers followed by a round where each judges the other's claims — contested claims sort to the top, because a claim two vendors argue about is where a person should look first. It exists because they fail differently: PR #9's redirect loop survived an adversarial review, 34 tests, `smoke.sh` and green CI, and the operator hit it on the first sign-in. Reviewers run read-only, and the harness does not trust the flag that says so — measured, `grok --permission-mode dontAsk` and `--permission-mode plan` both created a file they were told not to create, while `--sandbox read-only` refused three ways under bubblewrap. So every exchange records the exact argv, and the tree is photographed before and after: a read-only call that moved it fails with exit 3, naming the paths. A `--write` delegation lands in a throwaway worktree cut from `HEAD` and is never applied for you. Nothing runs in CI — a peer is non-deterministic, billed per call, and answers with an opinion. Protocol in `harness/peer.md`, decided in ADR-0014.

- **`harness/design/` — a design harness that measures first and argues second, and knows nothing about this repo.** Judging UI here was one agent, one screenshot, one opinion, and it spent that opinion on arithmetic: contrast ratios, hit-target sizes and sideways scroll are things a browser can be asked for exactly, and a model asked to eyeball them is slower and wrong at the edges. `design sense` drives every surface in `design.config.json` and answers with numbers — type scale, palette, radii, spacing grid, WCAG 2.2 contrast per *colour pair* rather than per element, target sizes with the spec's inline and spacing exceptions implemented, clipped and truncated text, the heading ladder as **rendered** (two levels at the same size is a hierarchy that exists only in the markup), layout shift, failed sub-resources — plus the measurable tells that make a page look generated: violet accent, violet→blue gradient, frosted panels, the 4px coloured left strip, three equal cards in a row, the badge above the headline, emoji as the icon set. Those are priors, not verdicts; a violet brand is allowed to be violet, which is what the contract in the profile is for. Then `design panel` puts the pixels to three critics with different lenses on different vendors' models, hands the findings **shuffled** to an adversary told to kill them and to refuse when torn, and gives an arbiter the pile with orders to rank by harm × exposure × cost of the fix and to *name* the disagreements rather than settle them quietly. Two speeds, never merged: `sense` is deterministic and could gate; `panel` is judgment, is billed per call, and is never a gate — a harness that fails a build on an opinion teaches everyone to stop reading it. A visual lens only runs on a runtime that can actually open an image (measured: claude yes, codex `-i` yes, grok 1.0.4 no), because a blind runtime handed PNG paths does not say so — it writes a confident critique of a page it never saw. Findings land as `report.md` and SARIF 2.1.0, so nothing downstream needs to know this harness exists. It is decoupled deliberately: `design.config.json` at the root is the only thing that names a host, a route, a persona or the product, and `design selftest` fails if the tree learns a second seam — it greps for our own words and then runs the entire deterministic pipeline from a scratch directory against fixtures, with no project present. The detectors are proven the way this repo insists: `fixtures/slop.html` breaks every rule on purpose, `fixtures/clean.html` is the same page built properly, and a rule that stays silent on the first fails, as does one that fires on the second — 63 assertions, all of them planted. Its first pass over this install found the shadcn input border at **1.26:1** where WCAG 1.4.11 wants 3:1, on every form; muted account copy at 3.99:1; and no `<main>` landmark on any signed-in surface. Decided in ADR-0015.

### Changed

- **The admin console has an identity block.** The foot of its rail was a bare "Sign out" — no name, no face, nothing to say which operator you were. That matters more there than on the product surface: every "View as" writes this person's address into `install_events`, and an operator who cannot see whose account they are in cannot tell whose name is going on the record. The presentational half of the product's avatar menu moved to `@hull/ui` as `UserMenu`, so both surfaces share the shape while disagreeing about the contents — the console has no account page, so it offers one item.

- **Account left the sidebar.** It is reached from the avatar menu at the foot of the rail, where Sign out already lived and where Vercel, Linear and Supabase all put it — a person looking for "things about me" goes to their own name, not to the product nav. Listing it in both places made a shell with one product surface look like it had two.

### Fixed

- **A test signed in as the seeded admin, which CI does not have.** `scripts/test.sh` migrates with `HULL_SEED_DEMO=0`, so `admin@hull.test` exists on a workstation only because an earlier run left it in `hull_test` — the container is reused and never dropped. The session-list test borrowed it, passed locally for that reason alone, and turned `main` red twice before anybody read the run. It now signs up an operator and promotes it, the way `test_handoff.py` already did. The trap is written into `AGENTS.md` and `HANDOFF.md`, with the delete that reproduces a clean database.

- **Three browser tests asserted the token was stripped from the address bar by reading the URL the instant `page.goto` returned.** `goto` resolves on `load`, which lands either side of the app's first render depending on the machine — so the check passed for months and then failed on every fragment page at once while the app was stripping correctly the whole time. Now polled, through one `expectTokenStripped` helper, which says out loud what a browser can and cannot tell apart: it proves the token does not survive in the address bar, and it cannot distinguish stripping during render from stripping in an effect one frame later. That distinction is kept where it belongs, in the comments in `Reset.tsx`, `Verify.tsx` and `EmailChange.tsx`.
- A rate-limited user was told **"Request failed"**. The edge answers 429 with a plain-text body, so the shared client fell through to `res.statusText` — empty over HTTP/2 — and every throttled sign-in, signup or reset ended in a message that explains nothing and invites hammering the button. It now reads "Too many attempts. Try again in 6s.", built from the `Retry-After` the response already carries. Found by the browser suite, which is the only layer that reaches enough of them to trip the limit.

### Security

- The edge rate limit is **one bucket per threat instead of one bucket for everything**, and no longer matched by prefix. `PathPrefix(/v1/auth/)` swept in `signout`, which guesses nothing — it destroys a session the caller already holds — so it spent budget belonging to the endpoints that do take a credential. Sign-in, reset redemption, password change and hand-off redemption keep the tight budget that stops a spray (10/min, burst 20). Signup and forgot move to their own (30/min, burst 60): neither takes a secret or answers anything about one, and what they need limiting for is spam and mail-bombing. Sharing one bucket meant a burst of new accounts locked out everyone signing in from the same address — which, with the counter keyed on client IP, is every user behind one office NAT.

- An **agentic QA harness** (`harness/scripts/qa.sh`, protocol in `harness/qa.md`, ADR-0013). Every gate in this repo starts from nothing — pytest builds a fresh client, `e2e/` opens a clean browser, `smoke.sh` is a bare `curl` — which is correct for each and a shared blind spot. PR #9's redirect loop lived in it: it needed a browser that had been somewhere before, so review, 34 tests, smoke, the visual harness and green CI all missed it and the operator hit it on the first sign-in. The harness takes the starting state as an argument: personas (`anon`, `member`, `admin`) crossed with taints (`clean`, `legacy-cookie`, `stale`, `junk`, `carry`), where `legacy-cookie` is that duplicate-cookie shape in one flag and `carry` reopens whatever the last run left. Shell rather than MCP because Claude, Codex and Grok share a shell but configure MCP differently, and the one that had not would find the harness silently absent. Headless by default, with `--headed` for a real window and `qa.sh watch` to hand the same live session to a person. It is not a gate and does not run in CI; a finding worth keeping becomes an `e2e/` spec or a pytest case.
- First finding from it, and the reason the `legacy-cookie` taint exists: a duplicate-cookie migration costs exactly one request. Signed in, with an apex-scoped `hull_session` planted beside the host-scoped one, the first load renders the sign-in form and retires the apex cookie; the second is signed in again. Failing closed on an ambiguous `Cookie` header is the right call and it self-heals, but the user-visible symptom during a migration is one flash of the sign-in screen. By design, recorded rather than changed.

### Changed

- Documentation is split by audience and stability. `AGENTS.md` is agent guidance again — process, gates, and a one-line statement of each hard invariant — while the reasoning moved to `docs/adr/` in the Nygard format (Status · Context · Decision · Consequences). The rules stay in the file agents always read; only the *why* moved, so an agent still sees the invariant without following a link.
- `docs/domain.md` holds what User, Org and Install mean, plus signup, isolation, support and session rules. These are business rules, not architectural decisions, and were being carried in the agent file for lack of anywhere else.
- `harness/action-feedback.md` holds the write-confirmation contract, next to `benchmarks.md` and `visual-ux.md`, and now records what its four failure patterns actually look like — none of which were visible in code review.
- Locks say what they actually mean: **a lock is not "never", it is "not by accident"**. Each one guards against the change nobody argued for — a tutorial that did it differently, a library that pulled in a dependency. A change somebody does argue for is normal: write the ADR, mark the old one superseded, change the code. That path is open for every rule, and the bar scales with the blast radius rather than the rule being absolute. A rule with no way out does not get respected, it gets ignored — and then the thing it prevented arrives anyway with nothing written down.
- ADR-0008 and ADR-0009 record the session-cookie scope change *and that the first decision was superseded*. The absence of that record is why `HANDOFF.md` told readers not to rebuild auth immediately after auth was deliberately rebuilt. ADR-0011 captures the build-vs-adopt question for the login lifecycle as `Proposed`, undecided.

### Security

- The session cookie is **host-scoped**. It carried `Domain=.<apex>`, so a live 14-day token was attached to every request to `mail.`, `s3.`, `rustfs.` and `db.` — none of which authenticate anyone, and `SameSite=lax` does not separate same-site siblings. `app.` and `admin.` now hold separate sessions; signing out of one no longer signs out the other.
- Credentialed CORS lists only the two authenticated surfaces. The apex and `www` have no auth and never call the API with credentials.
- Admin "View as" no longer relies on the browser carrying the admin's session across hosts. It mints a **single-use hand-off token** (60s, hashed at rest, `schema/migrations/002_support_handoff.sql`) that the console passes in a **URL fragment** — never sent to the server, so it stays out of access logs and out of `Referer`. `POST /v1/session/handoff` redeems it in one atomic statement, re-checks `platform_admin` at redemption rather than only at mint, and creates a session that expires in 45 minutes instead of 14 days. The token is stripped from the address bar before the page renders.

### Changed

- `effective_org_id` is wired in and is now the only supported way to resolve the org a request operates on. It had **zero callers**: impersonation set an acting org, the chrome displayed it, and nothing scoped data by it — harmless while there is no product data, a cross-tenant bug the first time a module read an org off the session. The raw field is renamed `session_org_id` so every call site is a loud miss, the role check and the expiry check live in one place (`SessionPrincipal.acting()`) so the chrome and the data scope cannot disagree, and a test fails the build if anything outside `accounts.py` reads the raw field.
- Impersonation lives on the customer surface, not on the admin console: `POST /v1/admin/support` returns a hand-off token and leaves the caller's session untouched, and `DELETE /v1/admin/support` ends the impersonating session itself (204, cookie cleared) rather than un-setting a flag. The support banner's "Stop" returns the operator to the admin console.

- Credential endpoints are rate-limited at the edge. `/v1/auth/*` and `/v1/me/password` go through a Traefik `rateLimit` middleware (10/min per client IP, burst 20) on new routers at priority 200. Nothing throttled them before, so a breach list could be sprayed at full speed against an 8-character minimum. The counter is in Traefik's memory — `AGENTS.md` forbids adding Redis. Same limit in the dev edge: a dev override that behaves differently from prod is where rate-limit surprises come from.
- `dbgate` is no longer an unauthenticated SQL console on the live database. It gets `LOGIN`/`PASSWORD` from `HULL_DBGATE_USER`/`HULL_DBGATE_PASSWORD` — without them its auth provider is literally `none`, which is what made an owner-level console reachable from any page the developer happened to visit.

- Session cookie now carries `Secure`. It never did: the flag was derived from the connection scheme, and uvicorn ran with `proxy_headers` but no `forwarded_allow_ips`, so Traefik's `X-Forwarded-Proto` was dropped (uvicorn trusts only `127.0.0.1`, Traefik dials from a bridge IP) and every live install saw `http`.
- Changing the password now revokes **every** session including the caller's, and returns a fresh cookie. Previously the one token the code deliberately preserved was the caller's own — so a stolen cookie survived the action taken to revoke it, while the contract advertised "other sessions die".
- `migrate.sh` refuses to apply the demo seed unless `HULL_HOST` ends in `.test`. The seed installs a `platform_admin` whose password is printed in the README and defaulted to on for any host.
- Avatar uploads are refused on `Content-Length` before the body is buffered. The 5 MB cap ran only after the whole request was in memory, so one large upload could drive the API container into the gigabytes.
- Traefik gets the leaf certificate pair only, not the whole `deploy/certs` tree — which handed the container `ca/ca.key`, the key to a CA installed in the host and Windows root stores. New CAs are issued with name constraints limiting them to `.test`, `localhost` and `127.0.0.1`, so a leaked key signs nothing outside the lab. Existing installs still trust an unconstrained CA: `generate-certs.sh` now detects that and prints the rotation command rather than replacing a CA already in a trust store behind the operator's back. `HULL_CA_ROTATE=1` performs it, keeping the previous CA at `deploy/certs/ca.previous` so the rollback is real, and `trust-ca.sh` / `setup-windows.ps1` remove the old certificate instead of leaving two "Hull Local CA" entries with different keys.
- `generate-certs.sh` verifies every certificate it issues against its own CA and refuses to leave an unusable one in place. Name constraints make this reachable: a permitted subtree that misses a single SAN invalidates the whole certificate, which is exactly how the first attempt at this broke `localhost`.
- `signin` always spends the hash cost, so a missing account is not distinguishable from a wrong password by response time.
- The adapter no longer publishes FastAPI's generated docs at `/api/docs`, `/api/redoc` and `/api/openapi.json` — a second, divergent spec served unauthenticated on both the customer and admin hosts.
- The API binds `127.0.0.1` by default (the container image still sets `0.0.0.0`), so the host-side dev loop is not published to the LAN.
- `.gitignore` covers every dotenv variant, not just the bare `.env`.
- CI actions are pinned to commit SHAs and the workflow declares `permissions: contents: read`.

### Added

- `make ci` and `make ci-e2e` run the gate locally. The workflow now calls `scripts/ci.sh` and `scripts/ci-e2e.sh` and holds no logic of its own, so local and CI are the same code rather than two lists that drift — and "did I run what CI runs" stops being a guess. Runner-only steps (writing `/etc/hosts`, pulling images with backoff, installing browser system libraries) are behind a `CI` check; on a workstation the script instead fails early with the fix if the Hull hostnames do not resolve.

- Browser end-to-end tests in `e2e/` (Playwright), run in CI against the real compose stack — ten flows covering signup through to a workspace, sign out and back in, photo upload, profile save, password change, account closure, and the admin "View as" hand-off. This covers the layer that let **avatar upload ship broken**: the API was correct and every API test passed while the client built an unparseable request. Proven both ways — reintroducing that exact bug fails the suite, restoring the fix passes it. It runs as a separate CI job so the existing checks keep their ~90s feedback.

- `dbgate` is a first-class lab service at `db.<host>`, started by `up.sh` alongside Mailpit and RustFS rather than hidden behind a `studio` profile, and listed in the README host table. It always requires its own credentials — that is the lock; the Traefik `basicAuth` that briefly sat in front of it was dropped, because two password prompts on a daily tool is the kind of friction that gets worked around with a trivial password.

### Fixed

- **Avatar upload never worked.** The shared client set `Content-Type: application/json` on every request with a body, including `FormData`, which suppressed the multipart boundary — so the server could not parse any upload.
- **The documented `scripts/dev.sh` inner loop served nothing.** All three Vite configs bound `127.0.0.1` while the dev edge dials the docker host-gateway (502), and binding wider hit Vite's host check (403). They now use `host: true` with `allowedHosts` and an HMR client port for the TLS edge.
- **`setup-local.sh` never read `.env`**, so a white-label `HULL_HOST` never reached `/etc/hosts` while `up.sh` happily issued certificates and routers for it — a correctly configured, unreachable stack. It also backs up `/etc/hosts` and guards against a missing trailing newline.
- `.env` is now parsed the way compose parses it. `set -a && source` ran the file as shell, so `HULL_BRAND=Acme Corp` printed `Corp: command not found` and left the brand at its default in `config.json` while the containers got the right value.
- `dev.sh` writes its computed environment to `.env.dev` instead of discarding it; the inner-loop API was connecting to `:5432` rather than `HULL_PG_PORT`, with mail and object storage disabled.
- A non-UUID org id returned a bare `500` instead of the contracted `404`/`422`, and the plain-text body then broke the client's JSON parse. Ids are typed, and every unhandled error leaves as `problem+json`.
- Postgres readiness is probed over TCP with consecutive successes. The socket-only probe went green during `initdb`, so a first `up.sh` could run migrate against a closed port.
- `migrate.sh` applies each file and its tracking row in one transaction under an advisory lock. A mid-file failure used to commit the earlier statements and record nothing, wedging the runner permanently.
- `up.sh` waits for the edge to actually serve before printing `UP_OK`. `compose up -d` returns when containers start, not when they answer, so the README quickstart — `up.sh` then `smoke.sh` — could fail on health against a still-booting API.
- `up.sh` always rebuilds. Images are pinned at `:0.1.0`, so "build only when the tag is missing" meant every run after the first served the first build — and the visual harness judged pixels from stale code.
- Clearing a display name now clears it. `COALESCE` discarded the write while the UI reported "Profile saved".
- `preflight.sh` sees a listener on any bind address, not just `127.0.0.1`; `smoke.sh` asserts a successful switch before trusting the isolation 404, checks the `reason_code`, and no longer writes to a predictable `/tmp` path; `capture-ui.sh` asserts sign-in actually happened before capturing the signed-in surfaces; `prune.sh` scopes its image prune to Hull's own label.
- `render-edge.sh`'s dot-escaping survives sed, so the CoreDNS regex no longer matches `hull-test.` alongside `hull.test`.
- Uvicorn's startup and access lines are emitted through the JSON formatter, so the container's stdout is uniformly JSON as `AGENTS.md` claims.
- Pillow decode errors are mapped to `422`, not `500`; a closed account's photo is deleted from the object store.

### Changed

- **Sessions are per-device.** Every sign-in used to delete all of the user's other sessions, so signing in on a phone dropped the laptop to the sign-in screen mid-task.
- Action feedback, per the table now in `harness/action-feedback.md`: closing an account takes a confirmation dialog before it runs; a failed workspace switch, a failed support "Stop" and a failed admin "View as" now report and hold a pending state instead of being empty clicks; photo errors are inline rather than toasted; replacing a photo actually updates the chrome.
- `contracts/openapi.yaml` describes what the adapter does: a root `security` requirement with explicit public opt-outs (all sixteen operations were specified as unauthenticated, including `/v1/admin/*`), a `Problem` schema with the `reason_code` enum, the reachable error statuses, the admin response envelopes, and OpenAPI 3.1 union types instead of the ignored `nullable: true` that made the schema reject every signup response.
- The admin app has a catch-all route; unknown paths rendered a blank page.
- `scripts/lib/env.sh` is the one place `.env` is read.

### Added

- A **Lab** group in the admin sidebar linking to the services compose brings up next to the product — Mail (Mailpit), Objects (RustFS console) and Database (dbgate). They were reachable only by typing the hostname. Admin only: these are operator tools, not product surfaces. Hosts come from `labOrigin()` in `@hull/config`, built at runtime from `/config.json`, so a white-label apex follows without a rebuild and nothing is baked into the bundle.
- `scripts/test.sh` gates on `ruff check` and `ruff format --check`, so CI enforces them. The rule set is pinned explicitly rather than inherited: ruff widens its defaults between releases, and an implicit default would let a routine upgrade turn CI red on untouched code. FastAPI's injectors are exempted from B008 through `extend-immutable-calls` instead of silencing the rule, so a real `def f(x=[])` is still caught, and `E501` is left to the formatter.
